1. 目標と小さな成功条件

目標：副業としてのアフィリエイトを小さく試す。まずは記事ネタ出しを社員に任せる練習をする。

今回の成功条件（仮案）：

  • 架空の商品ジャンルで、読者の悩み別の記事ネタが3案そろう
  • 各案が、そのまま記事に展開できる具体性（見出し案・導入の方向）を持つ
  • 誇大表現や根拠のない数字が含まれていないことを、チェック担当が点検している

ペースは「まず今回1回」。収益や成果の数字は、まだ何も作っていません。

2. 誰にどんな価値を届けるか

届ける相手

商品に興味を持っていて、比較や選び方を探している人。

届ける価値

読者の悩み（選び方・価格・手間・不安など）に沿った、分かりやすい記事の切り口。

読者向けの成果物でも、公開・送信の許可ではありません。公開先や実在の相手の情報も使いません。

4. お願いから最終統合までの受け渡し順

  1. あなたがリーダーに依頼する（架空の商品ジャンルを渡す）
  2. リーダーが依頼を整理し、idea-planner に渡す
  3. idea-planner の3案を、リーダーが article-drafter に渡す
  4. 骨子を、リーダーが claim-checker に渡す
  5. リーダーが指摘を反映し、記事ネタ3案を1つにまとめる
  6. リーダーが成果物と分担ログを保存し、あなたに報告する

担当同士は直接やり取りせず、必ずリーダーを通します。これは運用の説明です。

6. 最初の実行計画とそのまま貼れる依頼文

  • 担当順：idea-planner → article-drafter → claim-checker → リーダー統合
  • 材料：あなたが渡す架空の商品ジャンルのみ
  • 作る成果物：読者の悩み別の記事ネタ3案（HTML）と分担ログ
  • 品質確認：具体性・誇大表現なし・架空の明示
  • あなたの確認ポイント：方針に大きな判断が出たとき、完成時

この計画を載せることは、仕事の開始や接続の承認ではありません。あなたが依頼文を貼るまで何も始まりません。

最初の依頼文（選択してコピー。ジャンルは例として「架空のコーヒー器具」を入れています）：

私が架空の商品ジャンル「架空のコーヒー器具」を渡します。読者の悩みごとの切り口で、アフィリエイト記事ネタを3案出してください。idea-planner、article-drafter、claim-checker の本物の担当者を順番に呼び出し、リーダーが受け渡しと最終統合をしてください。実在の商品名・価格・実績は使わず、成果物と分担ログを ai-company/outputs/ に新規保存してください。

採用技術と理由

HTML/CSSの静的1枚（サーバー・インストール不要でそのまま開ける）、Claude Code、.claude/agents/ のMarkdown定義（担当の役割を文章で編集できる）。

担当定義の例（idea-planner の先頭部分）

---
name: idea-planner
description: "アフィリエイト記事ネタを考える担当。リーダーから架空の商品ジャンルと読者像を受け取り、読者の悩み別に記事ネタの候補と切り口を返す。"
tools: Read, Glob, Grep
model: inherit
---

役割を変えたいときは、該当する .claude/agents/（識別名）.md の description と本文を編集します。ただし name を変える場合は CLAUDE.md の呼び出し名も合わせて直してください。

実行手順

  1. ai-company/index.html をブラウザで開く
  2. 内容を確認する
  3. 必要な材料（架空のジャンル）を決める
  4. 最初の依頼文をClaude Codeに貼る
  5. 出力と分担ログを確認する

検証手順

依頼後、ai-company/outputs/ の 分担ログ.md に、3名の担当が実際に呼ばれた記録があるかを確認します。記録がなければ、分担は動いていません。
